# Pine diagnostics over ADB

Use official Android SDK Platform-Tools. Enable USB debugging and authorize the
computer on the unlocked device, or use Android's normal wireless debugging
pair/connect flow. No root is needed. Enable Diagnostics in Pine first.

Run from Windows PowerShell 5.1 or PowerShell 7:

```powershell
.\tools\pine-diag.ps1 -ListDevices
.\tools\pine-diag.ps1 -Serial YOUR_SERIAL
.\tools\pine-diag.ps1 -Serial YOUR_SERIAL -SessionId SESSION_ID
.\tools\pine-diag.ps1 -Serial YOUR_SERIAL -TitleId 0100751007ADA000
```

Use `-AdbPath C:\Android\platform-tools\adb.exe` if adb is not on PATH.
Multiple devices prompt for a serial; `-NonInteractive` requires `-Serial` when
multiple devices are present. Unauthorized/offline devices fail with an actionable
message. Disconnects fail visibly; reconnect the device and rerun the collector.
It never clears device logs or copies ADB credentials.

The collector displays JSONL and writes UTF-8 files under `pine-diagnostics/`,
named by UTC collection date/time and event session. `-OutputDirectory` selects
another folder. Existing buffered logcat messages may be included; use a session
filter to isolate a run. A Title ID filter matches the event's top-level
`title_id` base launch context (case insensitive), retaining its DLC, guest,
stage and summary records. When that context is absent, empty or `unknown`, it
falls back to the event-specific `fields.title_id` for older/pre-launch records.
Records without either known identity are excluded. A DLC's own Data ID in
`fields.title_id` does not replace a distinct known base context; use the session
filter to inspect all of that run's content IDs. Session IDs match exactly, including case, and
are sanitized and hashed for distinct filenames. After 32 session files,
additional sessions share one overflow file to bound open handles.

Press Ctrl+C to flush/close files and stop the ADB child. `-DurationSeconds 60`
provides a bounded capture. These workstation capture files are not rotated;
choose a bounded capture duration when leaving the collector unattended.

## Tests (no Android hardware or game content)

```powershell
powershell -NoProfile -File .\tools\tests\pine-diag.Tests.ps1
pwsh -NoProfile -File .\tools\tests\pine-diag.Tests.ps1
```

Windows tests use the OS .NET Framework compiler for fake ADB and Visual Studio
C++ Build Tools (discovered through `vswhere`) with a Windows SDK to build small
native EOF and isolated-console fixtures.
The EOF fixture links only Kernel32, with no CLR or CRT startup, and remains alive
after closing stdout. A pipe probe distinguishes native EOF from an empty pipe
that still has a writer. On Linux, tests use Python 3 for fake ADB. Tests cover multiple/no devices,
unauthorized/offline devices, USB permission and discovery failures, closed or
disconnected streams, production-sink title/session filters, UTF-8 round-trip without
a BOM, collision-free session grouping, bounded overflow, retaining logs,
finite capture cleanup and PowerShell pipeline cancellation. A separate native
helper creates an owned console and process job, verifies its console contains
only the helper and the test PowerShell process, and sends one real Win32
`CTRL_C_EVENT`. It requires the collector to exit itself within ten seconds,
the original fake-ADB process to be gone before closing the job, and all twelve
complete UTF-8 fixture records to be readable with exclusive file access.
Failure cleanup cannot count as a passing Ctrl+C result. At `5ff61e81`, this
passed in Windows PowerShell 5.1 (31 ms from signal to exit) and pwsh 7.6.6
(78 ms); these are controlled CI observations, not device or physical-keyboard
latency measurements. Neither fixture changes the workstation script policy.

Valid fake-ADB records are replayed unchanged from
[`fixtures/native-sink.jsonl`](tests/fixtures/native-sink.jsonl) and
[`fixtures/native-sessions.jsonl`](tests/fixtures/native-sessions.jsonl). Both are
generated by a controlled host program linked with the production native sink;
the native test runner verifies them against newly generated output. See
[`tests/fixtures/README.md`](tests/fixtures/README.md) for provenance and regeneration.
They exercise the transport contract, not a device connection or a real DLC read.

A POSIX pseudo-terminal test sends an actual Ctrl+C character, checks flushed
UTF-8 and verifies the child exited:

```sh
python3 tools/tests/test-ctrlc.py
# Set PINE_PWSH to an absolute pwsh path if needed.
```

For Windows keyboard acceptance, run the collector with a device, wait for an
event, press Ctrl+C, verify the JSONL parses and no collector adb logcat process
remains. Fake ADB tests do not demonstrate a real Android connection or APK launch.
# Startup crashes

For an immediate process exit, start capture before launch without TitleId or
SessionId filters: `./tools/pine-diag.ps1 -IncludeCrashLog`. This retains a separate
bounded local main/crash-buffer trace with AndroidRuntime, DEBUG and libc as
well as the existing PineDiag JSONL. Review the raw trace privately before
sharing; it is not automatically redacted. No device logs are cleared.
See [the startup investigation guide](../docs/diagnostics-startup-crash.md).
